GNSS 없이 시간 기준으로 속도 레퍼런스를 주고, `/motor_feedback`으로 시작·종료 정지를 확인한다. 기존 `main` 컨테이너를 사용한다.
명령의 km/h는 RPM 환산값이며 실제 주행속도는 아니다. 고정 조향으로 확보된 직선 구간에서 시험한다.

# 공통 실행 준비

각 터미널에서 컨테이너 접속과 source를 각각 실행한다.

```bash
# 호스트
docker exec -it \
  -e CONTROL_IMAGE_ID="$(docker inspect --format '{{.Image}}' main)" \
  -e CONTROL_CONTAINER_ID="$(docker inspect --format '{{.Id}}' main)" \
  main bash

# main 컨테이너
cd /workspace

source /workspace/install/setup.bash
export PI_TEST_ROOT=/workspace/log/pi_load_20261025
export ROS_LOG_DIR="$PI_TEST_ROOT/ros/$(date +%Y%m%dT%H%M%S)-$$"
mkdir -p "$ROS_LOG_DIR" "$PI_TEST_ROOT/notes"

# 당일 한 번: 사용한 코드·이미지 정보 보존
git -C /workspace/src/control_manager rev-parse HEAD > "$PI_TEST_ROOT/notes/commit.txt"
git -C /workspace/src/control_manager diff > "$PI_TEST_ROOT/notes/working.diff"

  > "$PI_TEST_ROOT/notes/container.txt"

  /workspace/src/trans/trans/*.py /workspace/src/encoder_motor/encoder_motor/*.py \

```

# 모터 RPM 추종성능시험 — 부하

기존 자율주행·수동 콘솔과 별도 `trans`는 정지 후 종료한다. 아래 지원 launch의 송신기만 사용한다.

```bash
# 터미널 1 - 모터 피드백
ros2 run encoder_motor motor_rpm

# 터미널 2 - 조향 피드백
ros2 run encoder_motor steer_angle

# 터미널 3 - 기록 + 실차 송신
ros2 launch manual_control brake_test_support.launch.py \
  live:=true \
  log_root:=/workspace/log/pi_load_20261025/runs

# 터미널 4 - 시험 조작
# 0→10: 즉시 STEP → 정확히 3초 유지
# → 10→0: 즉시 STEP → 정확히 3초 유지 → 모터 0·브레이크 OFF 유지
# RPM 정착 여부는 명령 전환·프로파일 완료 시간을 바꾸지 않는다.
#옵션	뜻	현재 설정
#start-speed-kph	첫 번째 목표
#end-speed-kph	두 번째 목표
#startup-time-s	0→첫 목표까지 명령을 올리는 시간
#transition-time-s	첫 목표→두 번째 목표로 바꾸는 시간
#hold-time-s	각 목표를 최소한 유지하는 시간
ros2 run manual_control brake_step_test \
  --speed-transition \
  --feedback-source motor_rpm \
  --no-wait-for-settle \
  --no-brake-on-complete \
  --start-speed-kph 10.0 \
  --end-speed-kph 0.0 \
  --startup-time-s 0.0 \
  --transition-time-s 0.0 \
  --hold-time-s 3.0 \
  --acceleration-timeout-s 15.0 \
  --steering-deg 0.0 \
  --ros-args \
  -p cmd_topic:=/cmd \
  -p motor_feedback_sign:=1.0 \
  -p motor_feedback_timeout_s:=0.3 \
  -p settle_window_s:=0.5 \
  -p settle_range_rpm:=5.0 \
  -p settle_slope_rpm_s:=2.0 \
  -p min_moving_rpm:=5.0 \
  -p stop_rpm:=1.0 \
  -p rpm_stop_hold_s:=0.5
```

지원 launch의 GNSS observer는 실행되지만, 위 RPM 모드의 시작·정지 판정에는 관여하지 않는다.
기록 경로는 절대경로를 사용한다. `Permission denied: '/runs'`는 `$PI_TEST_ROOT`가 비어 있을 때 발생하므로 위 명령으로 실행한다.

## 조작·진행 조건

| 키 | 동작 |
| --- | --- |
| R | 정지 확인 후 시험 시작 |
| Enter / Space | 모터 0·브레이크 ON |
| Q / Ctrl+C | 정지 확인 후 종료 |

- **진행:** RPM 모드는 기본적으로 시간 기준이다. 측정값이 안정되거나 목표에 도달했는지와 관계없이 설정한 시간대로 명령을 바꾼다.
- **유지:** `hold-time-s`는 각 목표의 고정 유지시간이며 0도 허용한다. 전체 프로파일은 `startup + transition + 2×hold`초 후 모터 명령만 0으로 내리고 브레이크 OFF를 유지한다.
- **정착 옵션:** 위 시간 기준 모드에서 `settle_*`, `min_moving_rpm`은 전환·종료 조건으로 사용하지 않는다. 기존 방식은 `--wait-for-settle`로 선택한다.
- **예:** `startup=6`, `transition=0`, `hold=0`이면 R부터 6초간 첫 목표까지 상승 후 0 RPM 명령을 주며 브레이크는 OFF다.
- **정지:** `COASTING / MOTOR_ZERO`에서 유효 RPM 절댓값 ≤1이 0.5초 지속되면 COMPLETE다. COMPLETE 후에도 모터 0·브레이크 OFF 송신을 계속한다. 실제 차량 정지도 확인한다.
- **제동:** Enter/Space·Q/Ctrl+C, 피드백 무효·새 측정 0.3초 끊김은 제동한다. 15초 timeout은 프로파일 수행 중에 적용하며, 정상 완료 뒤에는 시간 경과만으로 제동하지 않는다.
- **부호:** 24일 시험의 전진 원값이 양수여서 `motor_feedback_sign:=1.0`을 사용한다. 전진 원값이 음수인 장비는 정지 후 `-1.0`으로 변경한다. 단위·보정계수는 임의로 바꾸지 않는다.

필요하면 별도 터미널에서 확인한다. `/cmd` publisher는 시험 노드 1개여야 한다.

```bash
ros2 topic echo /motor_feedback
# 위 echo를 Ctrl+C로 종료한 뒤
ros2 topic info /cmd --verbose
ros2 param get /brake_test motor_feedback_sign
```

## 시험 순서·PI 비교

위 기본 명령은 STEP이다. 저속 확인·램프 시험은 아래 표의 값으로 바꿔 실행한다.
`brake_step_test`라는 이름만으로 STEP이 되지 않으며, 상승·전환 시간을 각각 0으로 지정해야 한다.
그래프의 ref가 수직으로 바뀌면 STEP 명령이다. 실제 RPM은 모터의 응답에 따라 완만하게 변할 수 있다.
한 회차가 끝날 때마다 터미널 4 종료 → 터미널 3 기록 종료·이름 입력 → 다음 회차용 지원 launch 재실행 순서다.

| 시험 | start-speed-kph | end-speed-kph | startup-time-s | transition-time-s |
| --- | --- | --- | --- | --- |
| 저속 램프 | 3.0 | 2.0 | 3.0 | 2.0 |
| 출발·하강 STEP | 3.0 | 2.0 | 0.0 | 0.0 |
| 이동 중 상승 STEP | 2.0 | 3.0 | 2.0 | 0.0 |
| 0 RPM으로 하강 STEP | 3.0 | 0.0 | 3.0 | 0.0 |

`startup-time-s=0`이면 출발 STEP, `transition-time-s=0`이면 목표 전환 STEP이다.
RPM 모드의 두 번째 목표는 0도 가능하다. 0 목표에서는 브레이크 OFF로 RPM 0을 명령하고,
측정 RPM과 무관하게 지정한 hold 시간이 지나면 모터 0·브레이크 OFF를 유지한다. hold=0이면 전환 종료 즉시 이 상태가 된다.
전환시간이 양수이면 0까지 선형 감속한다. timeout·수동 정지·피드백 오류는 즉시 제동한다.

```bash
# 터미널 4 대체 명령 - 0→3 STEP → 3초 유지 → 3→0 STEP → 3초 유지 → 모터 0·브레이크 OFF 유지
ros2 run manual_control brake_step_test \
  --speed-transition --feedback-source motor_rpm --no-brake-on-complete \
  --start-speed-kph 3.0 --end-speed-kph 0.0 \
  --startup-time-s 0.0 --transition-time-s 0.0 \
  --hold-time-s 3.0 --acceleration-timeout-s 15.0 \
  --steering-deg 0.0 \
  --ros-args -p cmd_topic:=/cmd -p motor_feedback_sign:=1.0
```

- 현재 게인으로 기준선을 기록한 뒤, **완전 정지 상태에서 컨트롤러 설정 도구로 Kp 또는 Ki 하나씩** 바꾼다. ROS 시험 노드에서 게인을 설정하는 기능은 없다.
- 같은 하중·노면·진행 방향에서 각 STEP을 3회 반복한다. 지연·오버슈트·진동·정상상태 오차를 비교하고 최종 브레이크 구간은 따로 본다.
- 회차별 **Kp/Ki·하중·배터리 전압·펌웨어·기록 폴더**를 `notes/`에 남긴다. 기록 이름 예: `부하_B00_step3to2_R01`.
- 2↔3 시험과 정지가 확인된 뒤 3↔5로 확대한다. 진동·충격이 커지면 정지 후 직전 게인으로 복귀한다.

# 시험 종료

정상 완료는 모터 0·브레이크 OFF다. 실제 정지·result/COMPLETE 확인 → 터미널 4 Q(명시적 제동·종료) → 터미널 3 q → y/n·기록 이름 입력.
지원 launch 종료로 trans도 종료한 뒤 피드백 노드를 종료한다.
`COMPLETE`여도 `operator_stop`·`acceleration_timeout`은 정상 프로파일 완료와 구분한다.
