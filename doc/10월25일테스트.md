# 10월 25일 자율주행 시험

작성 기준: 2026-10-25 KST. `10월24일테스트.md`의 자율주행 절차를 현재 소스에 맞춰 정리했다.
빌드와 기존 `main`·`dashboard` 컨테이너 실행이 완료된 상태에서 사용한다.

오늘 시험은 **예선 지도 기반 GNSS 경로 추종, 곡률·종점 감속, 콘솔 정지·재개**를 확인한다.
신호 정지, 우회전 전 3초 정지, 어린이보호구역·방지턱별 감속은 아직 자동화되지 않았다.
해당 지점에서는 운영자가 미리 `2/P`로 정지하고, 실제 정지·대기·전방 확인 후 `1/R`로 재개한다.
앞서 만든 정지선·감속구간 WP 후보는 주행 설정에 적용하지 않았다.

## 실행 방법

- 터미널 1~6은 **차량 PC 호스트의 새 터미널**에서 각 블록 전체를 복사해 실행한다.
- 각 블록이 기존 `main` 컨테이너에 접속하고 ROS 환경을 설정한다. 미리 `docker exec`로 들어가지 않는다.
- 터미널 7도 차량 PC 호스트에서 실행한다. 원격 조작 시에는 아래 SSH 접속 후 같은 블록을 실행한다.
- 터미널 5는 확인을 마치면 종료된다. 나머지는 실행 상태로 유지한다.
- 동일한 센서 노드·`trans`·자율주행 콘솔이 이미 실행 중이면 중복 실행하지 않는다. `/cmd`를 쓰는 수동/RPM 시험은 종료한 뒤 진행한다.
- 차량 이더넷과 센서를 연결한 뒤 실행한다. 이 문서는 네트워크 주소나 장비 설정을 자동 변경하지 않는다.

| 터미널 | 역할 |
|---|---|
| 1 | GNSS / NTRIP |
| 2 | 모터 RPM 수신 |
| 3 | 조향각 수신 |
| 4 | 주행 기록 |
| 5 | 지도·센서 확인 |
| 6 | `/control/actuator_raw` → 실제 UDP 송신 |
| 7 | 자율주행 콘솔·제어 노드 |

## 터미널 1 — GNSS

NTRIP 계정이 환경에 없으면 사용자명과 비밀번호를 입력한다. 비밀번호 입력은 화면에 표시되지 않는다.
GNSS 장치 경로는 전날과 같은 `/dev/ttyUSB0`이다. 다른 경로에 연결했다면 `device:=` 값을 변경한다.
후륜축 기준 변환을 위해 안테나 전방 오프셋 `0.559m`를 적용한다.

```bash
docker exec -it \
  -e NTRIP_USERNAME -e NTRIP_PASSWORD \
  main bash -lc '
set -e
source /opt/ros/humble/setup.bash
source /workspace/install/setup.bash
cd /workspace
export ROS_LOG_DIR="/workspace/log/ros/autonomy_20261025/gnss-$(TZ=Asia/Seoul date +%Y%m%dT%H%M%S)-$$"
mkdir -p "$ROS_LOG_DIR"
if [ -z "${NTRIP_USERNAME:-}" ]; then
  read -r -p "NTRIP 사용자명: " NTRIP_USERNAME
fi
if [ -z "${NTRIP_PASSWORD:-}" ]; then
  read -r -s -p "NTRIP 비밀번호: " NTRIP_PASSWORD
  printf "\n"
fi
test -n "$NTRIP_USERNAME"
test -n "$NTRIP_PASSWORD"
export NTRIP_USERNAME NTRIP_PASSWORD
exec ros2 launch gnss_0920 gnss.xml \
  device:=/dev/ttyUSB0 \
  ntrip_enabled:=true \
  antenna_offset_x:=0.559
'
```

## 터미널 5 — 지도·센서 확인

예선 지도 5,032점과 진행 추적 프로필의 일치를 확인한다. 이어서 센서 값을 한 번씩 표시한다.
5초 안에 샘플을 받지 못하면 오류로 끝나므로 해당 노드·연결을 확인하고 다시 실행한다.
모터·조향 피드백은 `valid=true`, GNSS는 현재 시각으로 계속 갱신되는지 확인한다.
정지 중 GNSS heading이 아직 없을 수 있으므로 출발 방향과 초기 직진 구간을 확인한다.

```bash

python3 -B - <<PY
```

## 터미널 7 — 자율주행 콘솔

차량 PC 호스트에서 아래 큰 블록을 실행한다. **원격 노트북**에서 조작한다면 먼저 SSH로 차량 PC에 접속한 뒤 실행한다.
차량 PC에서 직접 조작하는 경우 SSH 블록은 생략한다.

```bash
ssh -t baqu4@100.99.212.85
```

아래 기본값은 최고 10km/h, 가속·일반 감속 명령 변화율 2.0(km/h)/s다.
전날 문서의 최고 20km/h로 시험하려면 `CONTROL_TRIAL_SPEED_KPH=10.0` 한 줄을 `20.0`으로 변경한다.
직진 조향 영점 실측값이 있으면 `CONTROL_TRIAL_STEERING_ZERO_DEG`에 그 값을 같은 부호로 넣는다.

원본 YAML 대신 이번 실행용 설정 사본을 만든다. 지도·진행 추적은 예선용을 유지하고,
현재 미구현인 미션·인식 기반 제어 의존성은 비활성 상태로 실행한다.

```bash
docker exec -it \
  -e CONTROL_IMAGE_ID="$(docker inspect --format "{{.Image}}" main)" \
  -e CONTROL_CONTAINER_ID="$(docker inspect --format "{{.Id}}" main)" \
  main bash -lc '
set -e
source /opt/ros/humble/setup.bash
source /workspace/install/setup.bash
cd /workspace
export ROS_LOG_DIR="/workspace/log/ros/autonomy_20261025/control-$(TZ=Asia/Seoul date +%Y%m%dT%H%M%S)-$$"
mkdir -p "$ROS_LOG_DIR" /workspace/log/control_console/autonomy_20261025
CONTROL_TRIAL_SPEED_KPH=10.0
CONTROL_TRIAL_STEERING_ZERO_DEG=0.0
CONTROL_TRIAL_CONFIG_DIR=$(mktemp -d /workspace/log/control_console/autonomy_20261025/config-XXXXXX)
CONTROL_TRIAL_OPERATION="$CONTROL_TRIAL_CONFIG_DIR/operation.yaml"
python3 -B - "$CONTROL_TRIAL_OPERATION" <<PY
import sys
from pathlib import Path
import yaml
source = Path("/workspace/src/control_manager/config/modes/preliminary_lap.yaml")
data = yaml.safe_load(source.read_text())
common = data.setdefault("/**", {}).setdefault("ros__parameters", {})
common["mission_limit_enabled"] = False
common["mission_sections_enabled"] = False
common["object_state_enabled"] = False
data["/control/vehicle_interface"]["ros__parameters"]["dry_run"] = False
data["/control/control_selector"]["ros__parameters"]["start_paused"] = True
Path(sys.argv[1]).write_text(yaml.safe_dump(data, allow_unicode=True, sort_keys=False))
print("THIS RUN CONFIG:", sys.argv[1])
PY
exec ros2 run control_manager control_console \
  --mode preliminary_lap \
  --operation-file "$CONTROL_TRIAL_OPERATION" \
  --map-file /workspace/decision/script/map_generator/test/review/maps/MAP_preliminary.json \
  --variable-speed \
  --cruise-speed-kph "$CONTROL_TRIAL_SPEED_KPH" \
  --max-accel-kphps 2.0 \
  --max-decel-kphps 2.0 \
  --planned-decel-kphps 2.0 \
  --steering-zero-deg "$CONTROL_TRIAL_STEERING_ZERO_DEG" \
  --stopped-heading-max-distance-m 0 \
  --stopped-heading-max-reacquire-time-s 3.0 \
  --stop-speed-mps 0.1 \
  --stop-hold-s 0.5 \
  --log-root /workspace/log/control_console/autonomy_20261025
'
```

시작 직후에는 일시정지·모터 0·브레이크 ON 상태인지 확인한다.
콘솔의 지도·속도 상한·조향 영점과 `일시정지 상태로 준비됐습니다.` 표시를 확인한 뒤 `1/R`로 출발한다.

## 조작과 주행 시나리오

| 키 | 동작 |
|---|---|
| `1` / `R` | 출발·재개 |
| `2` / `P` | 모터 0·브레이크 ON으로 일시정지 |
| `0` / `C` | 모터 0·브레이크 OFF, 경로 추종 조향 유지 |
| `3` / `Q` / `Ctrl+C` | 정지 요청 → 실측 정지 확인 → 콘솔·제어 노드 종료 |

**정상 주행:** 시작점·시작 방향을 맞춘다 → 콘솔 일시정지 상태 확인 → `1/R` → 경로 추종과 곡선 감속을 확인한다.
종점에서는 자동 정지를 확인하고 `3/Q`로 종료한다.

**중간 정지·재개:** 원하는 정지점보다 충분히 앞에서 `2/P` → 실제 정지 확인 → 전방 확인 → `1/R`.
우회전 3초 정지 시험은 실제로 멈춘 뒤 3초 이상 대기하고 전방 확인 후 재개한다.
현재 자동 미션 기능의 성공으로 기록하지 않는다. 코스 중간에서 제어 노드를 재시작하지 않는다.

**비상상황:** 즉시 물리 E-stop → 차량 정지 확인 → PC 조작이 가능하면 `2/P`로 PC도 일시정지한다.
물리 비상정지 조작을 PC 키 입력 때문에 늦추지 않는다. SSH 단절 시 PC 키 요청의 전달을 보장할 수 없다.
현재 PC에는 실제 E-stop 상태가 자동 연동되지 않으므로, 해제 전에 PC가 모터 0·브레이크 ON 명령을 유지하는지 확인한다.
모터 보드가 ASMS ESTOP(mode 3)을 받았다면 새로운 ASMS AUTO 명령이 필요하며 PC의 `1/R`만으로 해제되지 않는다.
조향·브레이크 보드의 권한 복구도 확인한다. 실제 비상정지 후에는 원인을 확인하고 시작점에서 새 회차를 준비한다.

`0/C`는 브레이크를 거는 정지가 아니다. 정지가 필요하면 `2/P`, 비상상황에는 물리 E-stop을 사용한다.
정지 중 차량을 밀거나 돌렸거나 GNSS 원점·제어 노드가 재시작됐다면 시작점에서 새 회차를 준비한다.

## 설정 해석

- 최초 heading 확보에는 실제 속도 0.7m/s(2.52km/h) 이상이 필요하다. 최초 직진 확보 구간의 제한은 10초다.
- 정지·재개는 마지막 유효 heading을 제한적으로 사용한다. 전날과 동일하게 거리 제한은 0으로 해제하고, 실측 이동 시작 후 새 heading 확보 제한은 3초로 둔다. 정지 대기시간은 이 3초에 포함되지 않는다.
- 재개 후 heading 확보 시간 초과 등으로 다시 정지하면 콘솔·로그의 사유를 확인한다. `R`을 반복해 보호 조건을 우회하지 않는다.
- `--max-decel-kphps`는 일반 속도 명령 감소율이고 `--planned-decel-kphps`는 곡선·종점 감속거리 계산의 가정이다. 여기서는 둘 다 2.0으로 맞췄다. 실측 감속 성능을 뜻하지 않는다.
- `2/P`, `0/C`, 종점·무효 입력 등의 정지 명령은 일반 가감속 제한을 우회한다. 실제 감속·제동은 차량 반응으로 확인한다.
- 실측 정지 확인 기준은 유효 GNSS 속도 0.1m/s 이하가 0.5초 유지되는 것이다. 모터 RPM=0이나 명령=0만으로 실제 차량 정지를 판단하지 않는다.
- 본선 지도 파일은 있지만 본선 전용 진행 추적 프로필은 아직 비활성이다. 오늘 기본 복사 명령은 예선 전용으로 유지한다. `MAP_brake.json`은 없어 제동검차 모드는 이 문서에 넣지 않았다.

## 종료와 기록 저장

1. 터미널 7에서 `3/Q`를 누른다. 실제 정지와 콘솔·제어 노드 종료를 확인한다. 실측 정지를 확인하지 못하면 콘솔이 종료 대기 상태에 머물 수 있다.
2. 터미널 4에서 `q` → 저장 여부 `y/n` → `y`이면 기록 이름을 입력한다. 예: `1025_예선_10kmh_정지재개_01`.
3. 터미널 6의 `trans`를 `Ctrl+C`로 종료한다.
4. 시험을 끝내면 터미널 1~3도 `Ctrl+C`로 종료한다. `dashboard`는 기존 모니터링 용도로 사용한다.

| 기록 | 호스트 경로 |
|---|---|
| 센서·제어·송신 이벤트 | `~/Workspaces/2026WS/main/log/vehicle_recorder/autonomy_20261025/` |
| 콘솔 키 조작·상태·launch 로그·실제 실행 설정 | `~/Workspaces/2026WS/main/log/control_console/autonomy_20261025/` |
| 터미널별 ROS 로그 | `~/Workspaces/2026WS/main/log/ros/autonomy_20261025/` |

본 회차에 실제 적용된 설정은 콘솔 실행 폴더의 `config/operation.yaml`과 `metadata.json`을 확인한다.
원본 모드 YAML, 이전 날짜 문서, 지도 JSON은 이 절차에서 수정하지 않는다.
