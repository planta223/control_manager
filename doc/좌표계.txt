좌표계는 크게 3종류로 나뉘며, 총 13개 frame이 존재한다.

1) 전역 좌표계
   map

2) 차량 좌표계
   base_link

3) 센서 자체 좌표계
   gnss
   imu_link
   os_sensor
   os_lidar
   os_imu
   camera_optical_frame
   camera_dep_rgb_optical_frame
   ...
   
===============================================================

map : 지도 좌표계

          +y North
                   ↑
             |
             |
             +──────→ +x East
           

===============================================================

base_link : 차량 기준 좌표계 (원점은 후륜축 중앙)

              +x
                    차량 전방
                     ↑
              |
       +y ← [차량]
                 좌측

+x = 차량 앞
+y = 차량 왼쪽
+z = 차량 위

GNSS Odometry 의 본질적 목표는,
map 에서 봤을 때 차량(base_link)이 어디에 있고 어느방향을 보고있는가를 알아내는 것이다.

===============================================================

gnss : GNSS 안테나의 측정 위치

       차량 앞
          ↑

            ● GNSS
        |
        |
   -----●-----     ← rear axle center
      base_link
      
주요 확인사항! 현재 코드에서는 base_link ->GNSS 로의 TF는 없다!
만약 그렇다면, 이상적으로 다음과 같은 센서 장착 위치 관계가 있어야 할 것이다. 확인할 사항이다.
base_link
   ↓
gnss

===============================================================

imu_link : IMU의 측정 위치

예를 들어 IMU가 차량에 정확하게 정방향으로 장착됐다면,
base_link x축 ≈ imu_link x축
base_link y축 ≈ imu_link y축

하지만 센서를 90° 돌려서 장착했다면,
imu_link의 +x
≠
차량의 +x

주요 확인사항! 현재 코드에서는 base_link ↔ imu_link 가 UNKNOWN 이다!

===============================================================

LIDAR 관련:
os_sensor
 ├── os_lidar
 └── os_imu
 
os_sensor: Ouster 장치 몸체 기준
os_lidar: LiDAR 광학/측정 기준
os_imu: Ouster 내부 IMU 기준
이 셋의 관계는 Ouster가 알고 있고 실제 transform도 있습니다.

하지만 문제는,
base_link
   ?
os_sensor
차량에 LiDAR를 어디에, 어느 방향으로 달았는지가 연결되지 않았습니다.
즉 LiDAR 내부 좌표계는 잘 정의되어 있는데 차량 좌표계와의 연결이 없음입니다.

===============================================================

카메라 관련:
camera_optical_frame
camera_dep_rgb_optical_frame

마찬가지로 base link 로의 TF 는 없다.
